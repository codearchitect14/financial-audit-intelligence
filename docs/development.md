# Development

## Prerequisites

- Docker and Docker Compose
- Python 3.12 (not 3.13 or newer: the ML wheel set is not reliably available there)
- [uv](https://docs.astral.sh/uv/)

## Setup

```bash
docker compose -f infra/docker-compose.yml up -d db
cd backend
cp .env.example .env
uv sync --extra dev
uv run alembic upgrade head
uv run uvicorn fai.main:app --reload
```

## Everyday commands

All run from `backend/`.

| Command | Purpose |
|---|---|
| `uv run pytest` | Test suite. Integration tests skip when no database is reachable. |
| `uv run pytest -m integration` | Only the tests that need Postgres. |
| `uv run ruff check . --fix` | Lint and autofix. |
| `uv run ruff format .` | Format. |
| `uv run mypy src` | Strict type check. |
| `uv run alembic revision --autogenerate -m "..."` | New migration. |
| `uv run alembic check` | Confirm models and migrations agree. |
| `uv run alembic upgrade head` / `downgrade -1` | Apply / roll back. |

## Conventions

- **Never read `os.environ` directly.** Everything goes through `fai.core.config.settings`,
  so every knob is discoverable in one place and tests can override cleanly.
- **Raise `AppError` subclasses**, not bare `HTTPException`. That is what keeps the
  error envelope consistent and keeps internal detail out of responses.
- **Log with `structlog`**, in key-value form, never f-strings. The request id is bound
  automatically.
- **Comments explain why, not what.** If a line needs a comment to say what it does,
  rename something instead.

## Migrations

Always review an autogenerated revision before committing it. Autogenerate is a
starting point, not an oracle. It routinely:

- emits third-party column types without their import (handled here by the
  `render_item` hook in `alembic/env.py`, which was added after exactly this failure);
- misses data migrations entirely;
- proposes destructive operations when a model is renamed rather than altered.

After generating, always run:

```bash
uv run alembic upgrade head
uv run alembic check       # must report no new operations
uv run alembic downgrade base && uv run alembic upgrade head
```

CI runs all three. The drift check has already caught one real defect (see
[data-model.md](data-model.md), timestamp defaults).

## Troubleshooting

**`port is already allocated` on startup.** This machine runs several Postgres
containers. This stack uses host port 5436; change `POSTGRES_PORT` in `infra/.env` and
`DATABASE_URL` in `backend/.env` together if it conflicts.

**Integration tests all skip.** The database is not reachable. Start it, then apply
migrations.

**`NameError: name 'pgvector' is not defined` in a migration.** An older revision was
generated before the `render_item` hook existed. Add `import pgvector.sqlalchemy` to
that file.

**WeasyPrint fails to import on Windows.** It needs native GTK libraries and is
therefore in the optional `reports` extra, installed only in the Linux image. PDF
export is not available in a local Windows environment.
